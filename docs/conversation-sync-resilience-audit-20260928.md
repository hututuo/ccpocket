## 职责与不变量

| 层 | 唯一职责 | 必须保持 |
| --- | --- | --- |
| Provider / rollout | 原始消息、身份、顺序 | 只读原记录，不能用标题、文本或时间猜身份 |
| Bridge | 有界读取、协议与当前传输基线 | 最新内容继续送达，部分窗口不能带删除 |
| Mobile 同步服务 | 当前代次、消息确认、恢复范围 | 旧代帧无权提交，单会话失败不能重启全部连接 |
| SQLite 热缓存 | 原子提交、身份合并、读取窗口 | 最新投影可读，最多 2000 条，源记录可分页恢复 |
| 会话页面 | 渲染已提交顺序、折叠 | 引导不折叠，最终回复在过程外，刷新不增加副本 |

## 新确认的容量问题

旧 Bridge 在同订阅累计 2000 个部分条目或其 32 会话证明缓存被淘汰后，持续抑制后续部分窗口。Mobile 即便绕过该保护也会因合并总数超限回滚。因此仅修复重连入口不能保证超长会话继续更新。

修复约定：新增可选能力 conversation_sync_bounded_hot_window_v1。声明该能力的 Mobile 在同一事务中合并稳定顺序、保留本次传入的全部条目、再保留尽可能多的较新旧缓存；超过 2000 条时淘汰最早的非本次条目，显式标记 hasEarlier 并重置历史游标。规范源和历史分页不变，不能把此热缓存称为完整离线归档。最新轮次缺口仍按原有元数据表达。

Bridge 对新能力客户端不再用累计 ID 集合作为停止发送条件；单帧/快照字节上限、单批条目上限和发送背压仍保留。旧客户端保留原保护。没有新能力时不得假装客户端可以安全淘汰缓存。
