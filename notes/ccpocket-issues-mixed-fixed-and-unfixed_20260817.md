# CC Pocket 历史问题与当前问题混合清单

> 本文件汇总了项目历史中反复出现过的问题。部分问题可能已经修复，部分仍未修复，部分需要重新通过当前源码、日志或真机确认；不能把本清单直接视为当前未解决问题列表。

## 1. 消息重复、消失与误发送

- 发送一条消息后，手机端出现两条、三条或更多相同消息。
- “正在发送”和“发送完成”同时保留，应该只是同一条消息状态变化。
- 发送成功后消息暂时消失，之后又出现在错误的历史位置。
- 手机端显示多条相同回答，但电脑端实际只收到一条。
- 旧的文字或图片 pending 消息在重新进入会话、重连或运行时重新挂接后被自动重新发送。
- 切换会话、退出页面或 Bridge 重连后，发送中的消息状态被重置。
- Bridge 已接收、排队、Provider 已接收、发送成功等状态混在一起，无法确认真实发送状态。
- 排队消息的勾选状态与实际 Bridge 队列状态不一致。

## 2. 消息顺序、轮次和最终回复错乱

- 当前轮用户消息被放到上一轮会话的开头。
- 当前进度被放进中间过程，或者旧的中间过程被显示成当前最终回复。
- 最终回复被错误折叠进思考或中间过程。
- 用户消息、思考、中间过程、工具调用、当前进度和最终回复相互穿插。
- 同一条工具调用或中间消息在多个位置重复出现。
- 消息时间戳与实际 Codex 顺序不一致。
- 退出重进后顺序暂时恢复，刷新或继续更新后又再次错乱。
- 同一轮消息被拆成多个轮次，多个轮次又被合并成一大段。
- 回退/修改消息后，原消息仍留在历史列表中，输入框和历史同时出现同一内容。

## 3. 增量同步和历史缓存不稳定

- Codex Desktop 已经产生新消息，手机端仍停留在旧历史。
- 首次进入只能看到最新几条，最近一轮或中间过程加载不完整。
- 点击重试后立即显示加载失败，实际没有有效发起补载。
- 已经加载过的历史下次重新进入又消失，需要再次加载。
- 刷新后最新内容消失，页面回退到旧缓存。
- 刷新过程中已有内容先变成空白、转圈或 loading，随后才重新出现。
- 同一会话的更新数量在 `0 → N → 0 → N` 之间反复变化。
- 只收到后面的增量，之前缺失的内容没有补齐。
- 大会话、长 rollout 或大量中间过程会导致最新消息迟迟不出现。
- 当前会话和首页显示的缓存时间点不一致。
- 页面退出后缓存没有及时保存最新消息，重新进入时又回到历史状态。
- 局部刷新错误地覆盖了整条会话或清空了可用内容。

## 4. Canonical、Runtime、Outgoing 多来源混乱

- Codex/app-server 的权威历史、Bridge 同步结果、运行时推送和手机 optimistic 消息同时写入界面。
- 同一条 Provider item 因不同来源产生两个或多个 ID。
- canonical 历史和 runtime overlay 同时显示同一条 assistant/tool 内容。
- runtime overlay 在 canonical 提交后没有被清理。
- 重连或 authority generation 变化后，旧 turn 的消息再次进入当前会话。
- Duplicate canonical 被检测出来后只是隐藏，来源和生成路径没有被解决。
- Bridge 托管和 Codex Desktop 托管走不同路径，两个路径的状态、时间戳、消息和控制能力不一致。
- 共享模式、独立模式、private app-server、managed app-server、external app-server 的行为不一致。
- 手机端看到的运行状态与电脑端实际运行状态不一致。

## 5. Bridge 连接、订阅和进入会话不稳定

- 进入会话时进度卡在 5%、60%、79%、82%、84%、88%、89% 等固定检查点。
- 进度会从较高百分比跳回较低百分比并循环。
- WebSocket 实际稳定连接，但手机一直显示“正在载入会话运行状态”。
- 进入首页或会话页后，顶部长期显示未知、待同步或等待 Bridge。
- 每次退出会话都会短暂显示“Bridge 已断开，正在自动重连”。
- 正常页面切换会触发全局连接重建或重连提示。
- 首页订阅和会话订阅的生命周期不清楚，可能重复订阅或互相销毁。
- 进入会话、刷新、重连会影响其他会话的实时更新。
- 进度检查点过少且集中在后半段，无法判断实际卡在哪一步。
- 使用固定总超时时间，长会话或正常慢步骤被过早判定为超时。
- 重试、刷新按钮经常无效或只改变 UI 状态。
- 局域网连接、Tailscale 连接、IP 路线和 Bridge 身份之间出现混乱。
- 密钥错误、Bridge 不可达、Bridge 离线和服务未就绪没有稳定区分。

## 6. 顶部模型、思考强度、Plan、权限和额度字段异常

- 模型、思考强度、速度、Plan、审批权限、Token 额度和运行状态有时显示未知。
- 某一个字段缺失时，整个顶部设置栏一起变成未知。
- 电脑端是 `max/ultra`，手机端却显示 `high` 或其他值。
- 切换会话后模型、思考强度和 Plan 消失，退出重进后才恢复。
- 额度能显示，但模型、思考强度、权限或 Plan 不能显示。
- 设置修改成功后，界面短时间显示旧值，离开页面再回来才显示新值。
- Detached/shared 会话被错误显示为不可修改或由 Desktop 托管。
- 已经是共享线程后，手机仍被阻止修改模型、Plan、权限或停止运行。
- `unknown`、`notLoaded`、`idle`、`ready`、`working` 等状态语义相互混用。
- 同一个“处理中”状态在卡片、顶部栏、下载按钮旁边出现多套表示。
- 顶部字段宽度不足，文字互相挤压、覆盖或堆叠。
- 顶部浮动栏遮挡消息内容，字段自动换行后布局跳动。

## 7. 中间过程、思考和工具调用展示异常

- 多段中间过程被合并成一大段文本。
- 中间过程的结束边界无法识别，光标持续闪烁。
- 下一段中间过程直接接在上一段末尾，没有新的分组。
- 中间过程更新数量反复变化，甚至突然出现几千条更新。
- 工具调用、思考、当前进度和最终结果的分组不稳定。
- 展开后的工具调用或思考内容在消息更新时被折叠回去。
- 临时输出、工具调用和最终消息之间的时间戳位置不稳定，造成大量空白高度。
- 已经展开的消息在刷新后 Widget identity 改变，滚动位置跳动。
- 当前进度和最新消息互相覆盖或显示为旧轮次内容。

## 8. 会话列表、项目和名称同步异常

- 手机端显示两个或多个 Codex 项目，但电脑端实际上只有一个。
- 手机端出现电脑端不存在的临时项目、worktree 项目或旧项目。
- 同一个项目会自动展开、数量反复变化或被重复列出。
- 手机端项目名称和电脑端不同步。
- 手机端修改名称后覆盖电脑端名称，或者电脑端名称覆盖手机端名称。
- 同名会话被错误合并，打开不同会话却显示相同内容。
- 不同 IP 连接同一个 Bridge 时被拆成多个缓存和多个项目。
- 机器身份、Bridge 身份、数据源身份、IP 路线和项目路径没有清晰分层。
- 归档、删除、重命名、置顶和项目筛选后的列表不能稳定收敛。

## 9. 会话设置、控制和命令操作异常

- 停止按钮点击后没有实际停止运行中的 Codex turn。
- 重试按钮点击后没有重新读取缺失内容。
- 手动上下文压缩和自动压缩混在同一个工具调用或轮次中。
- 手动压缩后的排队消息不会自动继续，或者错误地自动发送。
- `/compact` 命令与顶部上下文压缩按钮行为不一致。
- 手动压缩没有独立的时间线分割线，错误归入上一轮工具调用。
- 手动发送的排队消息在上下文压缩结束后仍停留在队列中。
- 回退接口使用已弃用的 `thread/rollback`，且没有实现 Codex“修改此消息”的语义。
- 修改消息后无法正确截断当前轮次或重新开始后续会话。
- Goal 从顶部设置或斜杠命令设置后一直显示加载中。
- 自动批准只在手机端生效，手机退出后无法继续批准。
- Desktop 托管会话的手机控制按钮消失或不可用。

## 10. 诊断日志和快照上报异常

- 手机端出现问题时，电脑端日志与 Codex Desktop 实际历史对不上。
- 快照没有包含具体稳定 ID、来源、revision、turn、generation 等关键字段。
- 快照上传后被 Bridge 以认证字段、正文扫描或其他不明确原因拒绝。
- 不同错误都显示成同一个“诊断上报失败”，无法判断失败阶段。
- 快照有时为空或页面没有任何聊天记录，即使手机当时可见内容正常。
- 短暂闪烁、重复、消失和跳序状态无法被快照捕获。
- 日志只记录发送端，不记录真实接收端、SQLite 提交结果和最终 UI 投影。
- 诊断信息无法区分 canonical、runtime、outgoing、cache 和 UI 各层的内容。
- 日志中的消息 ID、时间、顺序和 Codex 原始 rollout 不一致。

## 11. Bridge 部署、运行模式和开发环境异常

- Bridge 候选构建成功但生产切换失败，失败原因经常在执行器权限、daemon、writer lease 和应用层错误之间混淆。
- Bridge 切换会影响托管在 Bridge 下的 app-server 或正在运行的会话。
- 共享 app-server 与独立 app-server 的启动、重连和交接行为不稳定。
- Codex Desktop、Codex CLI、Bridge 和手机端没有稳定使用同一个 app-server 来源。
- 生产 Bridge 版本、源码 HEAD、LaunchAgent 入口和实际监听进程有时不一致。
- IPA、OTA、Bridge runtime 和手机实际安装版本之间缺少可靠对应关系。
- 发布流程过长，重复执行大量无关测试和构建步骤。
- 构建通过后仍然无法证明真实手机链路可用。

## 12. 测试无法反映真实问题

- 一两千个局部测试全绿，但手机端仍然大量重复、消失、错序和刷新失败。
- 测试只覆盖单个 parser、model 或 widget，没有覆盖 Provider 到 UI 的完整链路。
- 使用假 Bridge 后测试绕过了真实 Bridge 的协议、SQLite、ACK 和同步问题。
- 测试没有覆盖真实消息、真实 rollout、真实分页、重连、乱序、重复和缓存回退。
- 测试 expected 与实现使用同一套生成逻辑，导致错误实现也能通过。
- 没有可观察的真实接收端，无法确认手机实际收到什么、写入什么、最终显示什么。
- 没有测试首页订阅、会话订阅、runtime overlay、canonical commit 和 UI projection 的组合行为。
- 没有测试长会话、大量中间过程、重复稳定 ID、旧 pending 消息和跨页面生命周期。
